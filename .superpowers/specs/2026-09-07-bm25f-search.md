# BM25F 搜索设计

- 状态：已确认设计的实施细化
- 日期：2026-09-07
- 范围：Stage 5A

## 目标

在保留 direct 为默认和可靠回退的前提下，实现完整、显式启用、可解释且可增量维护的本地 BM25F。索引始终是可删除缓存；Markdown、来源记录和原始对象仍是事实来源。

## 用户契约

```yaml
search:
  mode: bm25
```

```text
kb cache rebuild --vault <PATH_OR_ID>
kb query <QUERY> [--scope wiki|sources|all] [--strict-backend]
```

BM25 模式只读取当前且完整的索引。索引缺失、损坏、版本未知或与真实文件哈希不一致时，默认返回 direct 结果和明确 warning；`--strict-backend` 返回稳定错误，不回退。direct 模式完全不依赖 BM25 索引。

`cache rebuild` 在 BM25 模式下更新 `.kb/cache/bm25.json`。它比较实际文档集合和内容指纹：复用未变化文档的块，重建新增或变化文档，删除已不存在文档。索引可随时删除并从 Vault 重建。

## 分块与字段

每个 Markdown 标题区段或提取器正文块是一个检索块。以下字段分别记录长度和词频：

| 字段 | 权重 |
| --- | ---: |
| title | 3.0 |
| aliases | 2.5 |
| heading | 2.5 |
| tags | 2.0 |
| body | 1.0 |

Wiki 文档从 OKF/YAML frontmatter 读取 title、aliases 和 tags；来源使用来源标题，来源记录中的人工说明作为独立可引用块。未知字段不进入 BM25F。

ASCII 字母和数字按连续词元、小写处理。中文及其他无空格 Unicode 字符序列生成 1–3 gram；标点和空白分隔序列。查询和索引使用同一 tokenizer，不调用语言模型或外部分词服务。

## 计分与解释

每个查询词在块内使用 BM25F：先按字段权重和字段平均长度归一化词频，再应用 BM25 饱和与 IDF。固定参数为 `k1=1.2`，各字段 `b=0.75`。结果按总分降序，再按可移植 path 和位置排序。

为避免跨平台浮点序列化差异，公开分数和字段贡献四舍五入为百万分之一整数。每个 BM25 命中返回后端、总分、规范化查询词和各命中字段的词项/贡献；direct 结果不伪造 BM25 解释。

## 索引格式与完整性

索引包含 `schema_version: v1.0`、`indexer_version: bm25f-v1`、全局 generation、字段参数及文档列表。每个文档记录 scope、用户可见 path、实际 content path、精确来源 URI、内容指纹、generation 和检索块。

查询前枚举实际目标 scope 并核对路径集合和内容指纹。来源对象仍执行 SHA-256 完整性检查。任何不匹配都使整个请求的 BM25 后端不可用，不能混用部分旧索引和部分新文件。

## 写入与失效

缓存更新取得 Vault 独占锁并原子替换索引。知识保存成功后删除 catalog 和 BM25 索引；来源保存成功后也删除两者。失效失败只在知识或来源已经有完成凭据后作为 warning，不回滚事实文件。

## 非目标

- 不自动切换搜索模式。
- 不实现 Embedding、rerank、语义扩展或 LLM 回答。
- 不让索引成为备份或来源证据。
- 不在本阶段实现后台监听器；显式重建和查询前哈希核对保证正确性。
