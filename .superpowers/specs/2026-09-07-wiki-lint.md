# Wiki lint 设计

- 状态：已确认，进入实现
- 日期：2026-09-07
- 范围：Stage 3A

## 目标

`kb lint` 离线、确定性地检查 `Wiki/` 的 OKF v0.2 结构、Knowledge-Brain Producer Profile、文件链接、来源版本引用和跨平台路径。命令只返回事实与修改建议，不修改 Wiki、缓存、运行记录或日志。

检查结果由 `kb-app` 返回为稳定的 `LintReport`。CLI、未来 MCP、HTTP、WebUI 和 GUI 复用同一报告；CLI 的 `--strict` 只把“报告中存在发现”映射为非零退出码，不改变检查项目或报告内容。

## 扫描范围

- 扫描 `Wiki/` 下的 Markdown 文件。
- `Wiki/external-sources/.objects/` 是原始字节存储，不作为 Markdown 扫描。
- 所有路径先经过现有可移植路径和链接安全检查；不跟随符号链接或 Windows reparse point。
- `index.md` 和 `log.md` 使用 OKF 保留文件规则；其他 `.md` 文件是 concept 文档。
- 检查使用 Vault 的读取上限，避免无界遍历或读取。

## OKF v0.2 底线

普通 concept 文档必须：

- 以 UTF-8 编码；
- 在文件开头包含闭合且可解析为 YAML mapping 的 frontmatter；
- 包含非空字符串 `type`。

未知 `type`、未知顶层字段和未知扩展字段合法。可选字段存在时，lint 校验 OKF 定义的结构：`generated.by`、`verified[].by` 使用 actor 约定；来源 `resource` 非空；`generated.at`、`verified[].at`、`stale_after`、`sources[].last_modified` 和 `usage_window` 使用带 UTC offset 的 ISO 8601 时间；生命周期值合法。缺少可选字段不是普通 OKF 文档的错误。

Vault 根 `Wiki/index.md` 可以没有 frontmatter；存在 frontmatter 时只允许它承担 bundle 元数据，并校验 `okf_version: "0.2"`。其他 `index.md` 不使用 frontmatter。`log.md` 不使用 frontmatter，二级日期标题必须是 `YYYY-MM-DD`。

## Knowledge-Brain Producer Profile

只有 frontmatter 明确包含以下标记的 concept 文档属于受管理文档：

```yaml
kb:
  managed: true
```

不得根据目录、`generated.by` 或作者身份推断受管理状态。受管理 concept 在 OKF 底线上还必须包含：

- 非空字符串 `title`；
- 显式 `status`，值为 `draft`、`stable` 或 `deprecated`；
- `generated` mapping，其中 `by` 是非空字符串，`at` 是带 UTC offset 的 ISO 8601 时间；
- 非空 `sources` 列表，每项包含唯一的非空 `id` 和非空字符串 `resource`。

可选 `verified` 是单个 mapping 或 mapping 列表；每个事件包含非空 `by` 和有效 `at`。可选 `stale_after` 是带 UTC offset 的 ISO 8601 时间。`stable` 不意味着已验证，因此不要求 `verified`。

`kb.supersedes` 可选，值为字符串列表。每个值使用相对于 `Wiki/` 的可移植 `.md` concept 路径，不得指向自身、`index.md`、`log.md`、`.objects/` 或不存在的目标。反向的“被替代”关系由读取方推导，不写入文档。

## 来源引用

以 `kb-source://` 开头的 `sources[].resource` 必须是带 `?sha256=<64 位小写十六进制>` 的精确版本 URI，并与来源记录中的某个历史版本完全匹配。找不到版本是错误；引用存在但不是来源记录的当前版本是 warning。HTTP、HTTPS、bundle 相对路径和其他 OKF scope descriptor 保持开放，不被误判为 Knowledge-Brain 来源 URI。

## Markdown 链接与图检查

- 只解析标准 Markdown 链接；代码块中的文本不算链接。
- `http`、`https`、`mailto` 和其他带 scheme 的外部目标不做本地存在性检查。
- `#fragment` 指向当前文档；以 `/` 开头的路径相对于 `Wiki/`；其他路径相对于当前文件目录。
- 去除 query 和 fragment 后解析文件目标；百分号编码按 UTF-8 解码。
- 目标不得逃出 `Wiki/`，也不得进入 `.objects/`。
- 文件目标不存在时报告 warning。Stage 3A 不验证 heading fragment，因为不同 Markdown 消费者的 slug 规则不一致。
- `Wiki/research/` 与 `Wiki/articles/` 中没有任何入站 concept/index 链接的文档报告 orphan warning。`supersedes` 和 `sources` 中的 bundle 内路径也计为入站引用。
- `index.md` 中不存在的目标使用单独的 index-drift warning；Stage 3A 不要求索引列出全部文档，完整受管理区域同步由后续知识保存阶段实现。

## 报告契约

```text
LintReport
  schema_version
  checked_files
  findings[]

LintFinding
  severity: error | warning
  code: stable_snake_case
  path: Wiki-relative portable path
  line: optional one-based line
  message
  remediation
```

发现按 path、line、severity、code 排序。默认 `kb lint` 在成功生成报告时退出 0，即使报告有发现；`kb lint --strict` 在 findings 非空时退出非零，但 stdout 中仍返回成功报告。无法安全读取 Vault、配置或路径时仍返回普通命令错误。

## 非目标

- 不判断知识内容真假或语义矛盾。
- 不修改文件，不提供 `--fix`。
- 不生成或重写 `Wiki/index.md`、`Wiki/log.md`。
- 不实现知识写入 plan/apply。
- 不验证 Markdown heading fragment。
