# Knowledge-Brain v0.1.7

本版本修复 initialize-based MCP 客户端调用工具时携带 `_meta` 导致请求被拒绝的问题。CLI、Vault 数据格式、Agent Skills 和知识库使用流程没有变化。

## 如何升级

使用官方 Release 可执行文件安装时，在 Vault 目录中运行：

```bash
kb update
```

命令会先列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突；确认后才执行。更新完成后运行 `kb version` 和 `kb update status` 核对结果。

需要交给 AI Agent 时，将下面整句话中的路径替换为 Vault 路径并直接发送：

```markdown
请在 Knowledge-Brain Vault `<VAULT_PATH>` 中将 Knowledge-Brain 更新到 v0.1.7。使用系统 PATH 中已安装的 `kb`，先向我列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突，未经我确认不要执行；确认后完成全部更新步骤，并报告 `kb version` 和 `kb update status` 的最终结果。如果 CLI 替换后返回 `scheduled`，请等待替换完成并继续运行新版 `kb update`，不要停在中间状态。不要修改主题目录、`admission.yml`、普通笔记、Wiki 正文、Git 或 Obsidian 配置。
```

## MCP 兼容修复

- initialize-based MCP 的 `tools/call` 现在接受请求参数中的标准 `_meta` 字段。
- 修复 Hermes Agent 使用 mcp Python SDK 2.0.0 时，每次工具调用都因空 `_meta` 返回 `-32602 Invalid tools/call parameters` 的问题。
- legacy 与 modern 协议现在通过同一工具调用入口移除传输元数据，避免两条协议路径行为漂移。
- 工具参数仍保持严格校验；除 MCP 保留字段 `_meta` 外，其他未知字段不会被静默接受。

## 验证范围

- 使用 Hermes SDK 生成的空 `_meta` 请求形状完成回归测试。
- 通过真实 `kb mcp` stdio 进程验证 initialize-based 工具调用。
- modern MCP 工具调用与完整 `kb-mcp` 测试保持通过。

本次发布前未使用真实 Hermes Agent 完成端到端连接测试；该路径将在发布后使用正式二进制复核。
