# Knowledge-Brain v0.1.6

本版本修复 MCP Streamable HTTP 与 initialize-based 客户端的兼容问题，同时保留 `2026-07-28` modern 协议的严格校验。CLI、Vault 数据格式、Agent Skills 和知识库使用流程没有变化。

## 如何升级

使用官方 Release 可执行文件安装时，在 Vault 目录中运行：

```bash
kb update
```

命令会先列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突；确认后才执行。CLI 替换完成并显示 `scheduled` 时，等待替换结束，再运行一次新版 `kb update` 完成其余组件更新。最后运行 `kb version` 和 `kb update status` 核对结果。

需要交给 AI Agent 时，将下面整句话中的路径替换为 Vault 路径并直接发送：

```markdown
请在 Knowledge-Brain Vault `<VAULT_PATH>` 中将 Knowledge-Brain 更新到 v0.1.6。使用系统 PATH 中已安装的 `kb`，先向我列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突，未经我确认不要执行；确认后完成全部更新步骤，并报告 `kb version` 和 `kb update status` 的最终结果。如果 CLI 替换后返回 `scheduled`，请等待替换完成并继续运行新版 `kb update`，不要停在中间状态。不要修改主题目录、`admission.yml`、普通笔记、Wiki 正文、Git 或 Obsidian 配置。
```

## MCP Streamable HTTP

- 同一 `/mcp` 端点支持 initialize-based `2025-11-25`、`2025-06-18`、`2025-03-26` 和 modern `2026-07-28`。
- initialize-based 客户端可以完成 `initialize`、`notifications/initialized`、工具枚举和工具调用，不需要伪造 modern 专用的 `Mcp-Method` 或 `Mcp-Name`。
- modern 请求继续校验协议版本、方法、工具名和请求 `_meta`；旧协议兼容不会放宽 modern 请求。
- 未知版本返回 `-32022 Unsupported protocol version` 和受支持版本，不会静默降级。
- HTTP 服务保持无状态，不引入强制 `Mcp-Session-Id`、GET stream 或额外客户端配置。

## 互操作验证

- MCP Inspector 2.6.0 的默认 initialize-based 模式与显式 modern 模式均成功发现 12 个工具。
- Hermes Agent 0.21.3 通过原生 `mcp add` 和 `mcp test` 成功连接并发现 12 个工具。
- Claude Code 2.1.226 的默认 v1 HTTP 运行时完成握手并识别工具能力；测试环境的模型账号不可用，因此没有验证 Agent 实际调用工具。

## 兼容范围

本版本没有修改 Vault schema、模板版本、Skills 内容、索引格式或写入确认规则。Claude Desktop、OpenClaw、DeepSeek Harness、Pi 第三方 MCP 扩展，以及 Windows/Linux 原生网络入口尚未实测；不能由上述结果推断所有 MCP 客户端或全部认证模式均兼容。完整协议与部署边界见 [MCP 参考](../reference/mcp.md)。
