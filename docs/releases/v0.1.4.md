# Knowledge-Brain v0.1.4

本版本把 CLI、Vault 模板、已有受管理 Agent Skills 和搜索索引更新合并为一份可审阅计划，并补齐中断恢复、跨入口状态查询和固定 Vault 权限边界。

## 如何升级

使用官方 Release 可执行文件安装时，在 Vault 目录中运行：

```bash
kb update
```

命令会先列出待更新内容、跳过项与冲突，获得一次确认后才执行。完成后运行 `kb version` 和 `kb update status` 核对结果。

从 v0.1.3 升级时，第一次 `kb update` 使用旧更新器替换 CLI，并返回 `scheduled`。等待替换完成并确认 `kb version` 显示 v0.1.4 后，再运行一次 `kb update`，检查并更新 Vault 模板、已有受管理 Skills 和索引。

需要交给 AI Agent 时，将下面整句话中的路径替换为 Vault 路径并直接发送：

```markdown
请在 Knowledge-Brain Vault `<VAULT_PATH>` 中将 Knowledge-Brain 更新到 v0.1.4。使用系统 PATH 中的 `kb`，先向我列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突，未经我确认不要执行；确认后完成全部更新步骤，并报告 `kb version` 和 `kb update status` 的最终结果。如果当前版本是 v0.1.3，请在 CLI 替换完成后继续运行新版 `kb update`，不要停在 `scheduled` 状态。不要修改主题目录、`admission.yml`、普通笔记、Wiki 正文、Git 或 Obsidian 配置。
```

## 更新流程

- 裸 `kb update` 先显示完整组件计划，人类模式只在最终执行前确认一次。
- `kb update check` 保持只读且不持久化；`kb update --confirm <TOKEN> --json` 为 Agent 和 UI 提供精确确认；`kb update status` 返回持久最终状态。
- 多 Vault 更新支持在确认前排除指定稳定 ID。不同设备上的 Vault 路径仍由各设备注册表解析。
- 官方更新由已验证的目标版本程序规划其自身模板和 Skills；确认后跨进程替换 CLI，并由新程序继续处理其余组件。
- 文件在确认后变化时只把对应组件标为 `stale`，不会覆盖；独立组件继续执行。索引失败保留为 `rebuild_required`。
- 网络请求为暂时连接错误和 HTTP 408、429、500、502、503、504 提供有界重试，并对错误中的 URL 与凭据脱敏。

## Vault 与 Skills 安全

- 模板升级依据已登记的历史基线判断所有权；修改过的规则、schema 或未知模板整体跳过。
- 受管理 Skill 能区分旧版未修改、用户修改、部分缺失、外部安装和 legacy 安装，只升级仍属于 Knowledge-Brain 的内容。
- 状态和诊断会分别报告模板、索引、Skill 兼容性及未结束的更新操作。

## MCP 与 HTTP

- MCP 新增 `kb_update_plan`、`kb_update_status`，写入模式新增 `kb_update_confirm`。
- HTTP 新增 `/update/plan`、`/update/status` 和 `/update/confirm` 路由。
- 两种服务都固定使用启动时选择的 Vault，拒绝读取或确认另一个 Vault 或多 Vault 更新操作；确认仍要求 `--allow-write`，网络入口仍沿用现有 token 规则。
- 长时间运行的服务更新固定 Vault 的受管理组件，但不替换正在运行的服务程序；程序本身由本机 CLI 或服务管理方式更新。

## 兼容说明

Cargo、源码和第三方包管理器继续负责其安装的可执行文件。缺失或外部管理的 Skills 不会被自动安装或接管。主题目录、`admission.yml`、普通笔记、Wiki 正文、Git 和 Obsidian 配置不属于更新写入范围。
