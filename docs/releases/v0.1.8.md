# Knowledge-Brain v0.1.8

本版本补全从“搜索候选”到“读取完整知识”的链路。搜索片段继续只用于选择结果；CLI、MCP 和 HTTP 客户端可以使用稳定资源 URI 读取服务器 Vault 中的完整正文，并对长内容分页。

## 如何升级

使用官方 Release 可执行文件安装时，在 Vault 目录中运行：

```bash
kb update
```

命令会先列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突；确认后才执行。更新完成后运行 `kb version` 和 `kb update status` 核对结果。

需要交给 AI Agent 时，将下面整句话中的路径替换为 Vault 路径并直接发送：

```markdown
请在 Knowledge-Brain Vault `<VAULT_PATH>` 中将 Knowledge-Brain 更新到 v0.1.8。使用系统 PATH 中已安装的 `kb`，先向我列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突，未经我确认不要执行；确认后完成全部更新步骤，并报告 `kb version` 和 `kb update status` 的最终结果。如果 CLI 替换后返回 `scheduled`，请等待替换完成并继续运行新版 `kb update`，不要停在中间状态。不要修改主题目录、`admission.yml`、普通笔记、Wiki 正文、Git 或 Obsidian 配置。
```

## 完整知识读取

- 新增 `kb read <RESOURCE_URI>`，支持通过游标分页读取完整 Markdown 或已保存来源。
- 查询结果新增稳定的 `resource_uri`，并用 `path_scope: server_vault` 明确路径属于服务器 Vault，不应在 Agent 本机查找。
- MCP 新增 `kb_read`、`resources/list`、`resources/templates/list` 和 `resources/read`。
- Streamable HTTP 新增 `POST /resources/read`，与 CLI、MCP 使用同一读取规则。
- 服务状态不再暴露 Vault 的绝对路径，并明确报告远程访问模式。

## 读取边界

- 可读取 `KB.md`、Wiki 索引、受管理的 research/article 页面，以及精确保存的来源版本。
- 不允许借资源 URI 读取任意 Vault 文件、未保存的主题笔记、日志或内部来源记录。
- PDF 等当前没有可用文本提取结果的来源会明确返回 `text_available: false` 和说明，不伪造正文。
- 搜索片段仍限制为候选预览；客户端应使用返回的资源 URI 获取完整证据。

## 验证范围

- 本地 macOS ARM64 release 二进制完成初始化、准入、来源保存、精确查询和三页完整读取。
- 真实 MCP stdio 进程完成 initialize、工具发现、精确查询和完整读取，并兼容工具参数中的空 `_meta`。
- 真实 Streamable HTTP 服务完成 initialize、initialized 通知、精确查询和完整读取。
- 来源对象完整性校验和只读维护检查通过。

Linux、Windows 和 macOS 官方产物由正式发布工作流分别构建和验证。发布后仍需使用上一正式版本完成一次真实联网 `kb update` 验证。
