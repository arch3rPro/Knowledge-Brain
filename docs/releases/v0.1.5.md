# Knowledge-Brain v0.1.5

本版本完善多设备 Vault 的可选 Git 同步保护，并明确区分 Agent 受管理写入与人类直接编辑 Markdown 的边界。Git 仍不是使用 Knowledge-Brain 的前置条件。

## 如何升级

使用官方 Release 可执行文件安装时，在 Vault 目录中运行：

```bash
kb update
```

命令会先列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突；确认后才执行。CLI 替换完成并显示 `scheduled` 时，等待替换结束，再运行一次新版 `kb update` 完成其余组件更新。最后运行 `kb version` 和 `kb update status` 核对结果。

需要交给 AI Agent 时，将下面整句话中的路径替换为 Vault 路径并直接发送：

```markdown
请在 Knowledge-Brain Vault `<VAULT_PATH>` 中将 Knowledge-Brain 更新到 v0.1.5。使用系统 PATH 中已安装的 `kb`，先向我列出 CLI、Vault 模板、已有受管理 Skills 和索引的全部待更新内容、跳过项与冲突，未经我确认不要执行；确认后完成全部更新步骤，并报告 `kb version` 和 `kb update status` 的最终结果。如果 CLI 替换后返回 `scheduled`，请等待替换完成并继续运行新版 `kb update`，不要停在中间状态。不要修改主题目录、`admission.yml`、普通笔记、Wiki 正文、Git 或 Obsidian 配置。
```

## Git 同步保护

- 非 Git Vault 以及没有 upstream 的本地 Git 仓库保持原有行为，不增加网络或同步依赖。
- `kb sync check` 会比较当前分支与本机已有的 upstream 跟踪引用。外部执行 `git fetch` 后，本地落后或与上游分叉会阻止 Knowledge-Brain 的共享写入。
- Knowledge-Brain 不会自动执行 fetch、pull、merge、rebase、commit、push 或 force push。普通 push 仍是远程并发变化的最终检查。
- 新增可独立安装的 `kb-sync` Skill，用于已有 Git upstream 的同步流程；普通 Vault 不会因此自动启用 Git。

## Wiki 编辑与检测

- Vault 规则和 Agent 指南明确要求 Agent 不直接创建、修改、移动或删除 `Wiki/` 文件；明确的 Wiki 变更继续通过 `kb knowledge save` 统一维护正文、索引和日志。
- 人类仍可在 Obsidian 或文本编辑器中直接编辑 Markdown。
- `kb lint` 新增 `unmanaged_wiki_page`，用于发现误放进 `Wiki/research/` 或 `Wiki/articles/` 的普通页面。
- `kb lint` 新增 `index_missing_entry`，用于发现没有出现在生成索引中的受管理页面。
- 人工正文修改不会只因不是 CLI 写入而报错；需要恢复历史内容时使用用户已启用的 Git 历史或 Knowledge-Brain 备份。

## Vault 与 Skills 升级

- Vault 模板版本升级到 v1.3，为 Agent 写入 Wiki 和可选 Git 同步增加明确规则。
- 未修改的 v1.2 模板可以通过 `kb update` 或兼容入口 `kb vault upgrade` 审阅后升级；用户修改过的受管理规则仍会作为冲突保留，不会被覆盖。
- 内置 Agent Skills 从九项增加到十项。已有受管理安装通过 `kb update` 增加 `kb-sync`；外部安装和用户修改的 Skill 不会被接管。

## 兼容说明

本版本不要求 Vault 使用 Git，也不自动修改 `.gitignore`、`.gitattributes`、远程仓库或 Obsidian 配置。`kb sync check` 本身不联网，只能判断最近一次 fetch 后本机已知的 upstream 状态。
