# MCP Stdio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a fixed-Vault `kb mcp` stdio server whose tools reuse `kb-app` and default to planning without execution authority.

**Architecture:** A dedicated `kb-mcp` adapter owns bounded newline-delimited JSON-RPC framing, MCP lifecycle negotiation, tool schemas, and error conversion. It never reads Vault files itself. The CLI resolves one Vault ID before starting the server; read/planning tools bind that ID, while `apply_operation` is advertised and accepted only with explicit `--allow-write`.

**Tech Stack:** Rust 2024, Tokio stdio, serde/serde_json, existing `kb-app`, `kb-core`, and `kb-protocol` crates; no MCP SDK dependency while the official SDK requires Rust 1.88.

**Spec:** `docs/superpowers/specs/2026-09-07-knowledge-brain-design.md` sections 14, 17, 20, and 24.

## Global Constraints

- Rust MSRV remains 1.85.
- MCP uses stdio and requires no daemon, network listener, Node.js, Python, or Java.
- stdout contains protocol frames only; diagnostics go to stderr.
- The server fixes one Vault at startup and accepts no caller-supplied filesystem path.
- Default authority permits reads and creation of reviewable plans, not `apply`.
- Tool input is untrusted JSON with bounded line size and stable errors.
- MCP never exposes broader file access than CLI with the same authority.
