# HTTP API Implementation Plan

**Goal:** Add an optional authenticated HTTP adapter over the shared application layer.

**Architecture:** A new `kb-server` crate owns Axum/Tokio transport concerns and invokes typed `kb-app` requests. `kb-cli` only parses `serve` startup policy and runs the server. Vault rules stay in `kb-app`/`kb-core`.

**Spec:** `docs/superpowers/specs/2026-09-07-http-api.md`

**Verification constraint:** Run focused tests only; do not run the workspace-wide suite.

### Task 1: Server policy and dependencies

- [ ] Pin Rust-1.85-compatible Axum and Tokio versions.
- [ ] Define bind, token and write-policy validation independently of sockets.
- [ ] Test loopback, LAN, empty token and write-enable combinations.

### Task 2: Read and planning routes

- [ ] Add authenticated JSON envelope middleware and body limit.
- [ ] Route capabilities, status, doctor, query, lint, review, plan and operation inspection through `AppRequest`.
- [ ] Test real HTTP requests against a port-0 listener and fixed Vault.

### Task 3: Explicit apply permission

- [ ] Deny apply in read-only mode with `auth_denied`.
- [ ] Require a token whenever apply is enabled.
- [ ] Verify plan inspection and explicitly enabled apply without exposing arbitrary operation paths.

### Task 4: CLI lifecycle

- [ ] Add `kb serve` startup arguments and startup JSON line.
- [ ] Handle bind errors and Ctrl-C without a daemon or background installation.
- [ ] Run a real CLI subprocess journey for startup, auth and shutdown.

### Task 5: Documentation and focused verification

- [ ] Publish HTTP reference, security boundary, capability status and Stage 4A Roadmap entry.
- [ ] Record SSE as an explicit next slice rather than a placeholder endpoint.
- [ ] Run format, related crate Clippy, focused server/CLI tests and diff checks.
- [ ] Record unverified platform/TLS/SSE/full-suite limits explicitly.
