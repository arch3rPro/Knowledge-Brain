# BM25F Search Implementation Plan

**Goal:** Deliver optional, explainable BM25F with incremental cache updates and deterministic direct fallback.

**Architecture:** `kb-core` owns backend-neutral request/result and BM25 index contracts. `kb-app` owns tokenization, indexing, freshness checks and ranking behind the existing query workflow. `kb-cli` only maps `--strict-backend`; cache and query remain available to future adapters through `AppRequest`.

**Spec:** `docs/superpowers/specs/2026-09-07-bm25f-search.md`

**Verification constraint:** Run focused tests only; do not run the workspace-wide suite.

### Task 1: Public search and index contracts

- [ ] Add optional backend/score/explanation fields without changing direct semantics.
- [ ] Add strict-backend request policy and stable unavailable-index error.
- [ ] Define versioned BM25F index documents, chunks, fields and update report.
- [ ] Cover JSON compatibility and request validation with focused core tests.

### Task 2: Tokenization, BM25F scoring and explanations

- [ ] Write failing tests for ASCII terms, CJK 1–3 grams, field boosts, length normalization, deterministic ties and explanations.
- [ ] Implement a pure tokenizer and ranker independent of filesystem access.
- [ ] Verify only the scoring module tests.

### Task 3: Incremental index cache

- [ ] Write failing tests for initial build, unchanged reuse, add, update, delete, corruption and source integrity.
- [ ] Build document fingerprints and field-aware chunks from actual Wiki/source documents.
- [ ] Atomically update `.kb/cache/bm25.json`, preserving generation for unchanged documents.
- [ ] Validate complete scope/path/hash equality before query use.

### Task 4: Query dispatch, fallback and CLI

- [ ] Write a failing real CLI journey for BM25 ranking, CJK, explanations, stale fallback and strict failure.
- [ ] Dispatch direct or BM25 in `kb-app`; keep `scope=all` groups independent.
- [ ] Add `--strict-backend`, capability reporting and cache rebuild integration.
- [ ] Invalidate BM25 cache after successful source and knowledge saves.
